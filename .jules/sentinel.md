## 2024-03-25 - [Missing Authentication and Mass Assignment]
**Vulnerability:** The POST `/api/projects` endpoint lacked authentication and directly passed `req.body` to the Mongoose `Project` model. Also, string comparison for API keys needs to be timing-safe.
**Learning:** Endpoints meant to be private need explicit authentication middleware. Directly using `req.body` without destructuring exposes the application to mass assignment vulnerabilities where users can modify fields they shouldn't. Regular string equality checks for secrets can lead to timing attacks.
**Prevention:** Use an authentication middleware for all protected routes, employ `crypto.timingSafeEqual` with normalized buffer lengths for comparing secrets, and always explicitly destructure inputs before passing them to the database model.
## 2024-04-24 - Mass Assignment Vulnerability in Express Routes
**Vulnerability:** The Contact route accepted the entire `req.body` directly into the Mongoose model (`new Contact(req.body)`), which allowed attackers to overwrite sensitive schema fields with mass assignment. Specifically, an attacker could set the `status` field to `'read'` or `'replied'`, bypassing default initialization and potentially disrupting application logic or avoiding review.
**Learning:** Mongoose defaults and strict mode (`strict: true` by default) only strip out fields not defined in the schema. They do *not* protect against users setting values for fields that *are* defined in the schema but shouldn't be user-controllable (like `status`, `role`, or `isAdmin`).
**Prevention:** Always manually destructure and pick the allowed, safe fields from `req.body` before passing them to the model, or use a validation library to sanitize inputs. Avoid passing `req.body` directly to model constructors.
